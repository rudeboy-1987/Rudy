# 🚀 Deploy EstimatePro to Vercel + Render + MongoDB Atlas

End-to-end guide to put your live app at **https://donerightelectricltd.com**.

> **Architecture**
> ```
> Browser (PWA)
>     │
>     ▼
> donerightelectricltd.com  →  Vercel  (Expo Web export, static)
>     │   (only /api/* proxied)
>     ▼
> api.donerightelectricltd.com  →  Render  (FastAPI, Python 3.11)
>     │
>     ▼
> MongoDB Atlas  (free M0 cluster)
> ```

---

## STEP 1 — MongoDB Atlas (≈5 min, free)

1. Go to **https://www.mongodb.com/cloud/atlas/register** → create account.
2. Click **Build a Database** → choose **M0 FREE** → AWS / N. Virginia (`us-east-1`) → **Create**.
3. **Security → Database Access** → *Add new database user*:
   - Username: `estimatepro`
   - Password: click **Autogenerate** → **copy it now** (you'll only see it once).
   - Built-in role: **Atlas admin** (simplest) or **readWrite on estimatepro**.
4. **Security → Network Access** → *Add IP Address* → **Allow access from anywhere** (`0.0.0.0/0`). (Render's IPs rotate; we'll restrict later.)
5. **Database → Connect → Drivers → Python 3.12+** → copy the connection string:
   ```
   mongodb+srv://estimatepro:<password>@cluster0.xxxxx.mongodb.net/?retryWrites=true&w=majority&appName=Cluster0
   ```
   Replace `<password>` with the password from step 3. **Save this — it's your `MONGO_URL`.**

---

## STEP 2 — Render (Backend, ≈10 min)

1. Go to **https://render.com** → **Sign up with GitHub** → authorize the EstimatePro repo.
2. Dashboard → **New** → **Blueprint** → pick your `EstimatePro` repo → **Apply**.
   - Render reads `render.yaml` and creates a Web Service called `estimatepro-backend`.
3. After it scaffolds, click into the service → **Environment** tab → fill in these env vars (the ones flagged `sync: false` in `render.yaml`):

   | Key | Value |
   |---|---|
   | `MONGO_URL` | the Atlas connection string from Step 1 |
   | `DB_NAME` | `estimatepro` (already set) |
   | `EMERGENT_LLM_KEY` | from Emergent → Profile → Universal Key |
   | `PAYPAL_CLIENT_ID` | your live PayPal Client ID |
   | `PAYPAL_CLIENT_SECRET` | your live PayPal secret |
   | `TWILIO_ACCOUNT_SID` | from Twilio Console |
   | `TWILIO_AUTH_TOKEN` | from Twilio Console (**rotate first — old one leaked**) |
   | `TWILIO_PHONE_NUMBER` | `+18332428534` |
   | `SENDGRID_API_KEY` | optional, leave blank for now |

   `JWT_SECRET` is auto-generated by Render. `CORS_ORIGINS` is already in `render.yaml`.

4. Click **Manual Deploy → Deploy latest commit**. Wait ~3–5 min until status is **Live**.
5. Test it: open **https://estimatepro-backend.onrender.com/api/health** — you should see:
   ```json
   { "status": "healthy", "timestamp": "..." }
   ```
   **Copy this URL — you'll plug it into Vercel next.**

> 💡 Render free tier sleeps after 15 min idle and takes ~30 s to wake. Upgrade to **Starter ($7/mo)** for 24/7 uptime once you're getting real traffic.

## STEP 3 — Vercel (Frontend / PWA, ≈8 min)

1. Go to **https://vercel.com** → **Sign up with GitHub** → import your `EstimatePro` repo.
2. **Configure Project**:
   - **Framework Preset:** Other (Vercel will read `vercel.json` automatically)
   - **Root Directory:** `./` (leave default — `vercel.json` handles the rest)
   - **Build/Output:** leave defaults — `vercel.json` controls them.
3. **Environment Variables** → add **one** var:

   | Name | Value | Environments |
   |---|---|---|
   | `EXPO_PUBLIC_BACKEND_URL` | `https://estimatepro-backend.onrender.com` (your Render URL from Step 2) | Production, Preview, Development |

4. **IMPORTANT:** Open `vercel.json` in your repo and replace the placeholder on line 11:
   ```diff
   - "destination": "https://YOUR-RENDER-BACKEND.onrender.com/api/:path*"
   + "destination": "https://estimatepro-backend.onrender.com/api/:path*"
   ```
   Commit + push. (Or skip this — the frontend hits `EXPO_PUBLIC_BACKEND_URL` directly, so the rewrite is optional. Only matters if you want same-origin API.)

5. Click **Deploy**. Vercel will:
   - `cd frontend && yarn install --frozen-lockfile && npx expo export --platform web`
   - Serve `frontend/dist` on a `*.vercel.app` URL.
6. After ~3–5 min, open the Vercel preview URL — your green landing page with "Get Estimate" + "Find Pros" buttons should load.

## STEP 4 — Hook Up Your Ionos Domain (≈15 min, 1–24 h DNS propagation)

You own **donerightelectricltd.com** at Ionos. We'll point:
- **`donerightelectricltd.com`** + **`www`** → Vercel (frontend)
- **`api.donerightelectricltd.com`** → Render (backend)

### 4a. Add domain to Vercel
1. Vercel → your project → **Settings → Domains** → **Add** → type `donerightelectricltd.com` → Add.
2. Repeat for `www.donerightelectricltd.com`. Vercel will tell you which DNS records it needs.

### 4b. Add domain to Render
1. Render → your service → **Settings → Custom Domains** → **Add Custom Domain** → `api.donerightelectricltd.com`.
2. Render gives you a CNAME target like `estimatepro-backend.onrender.com`.

### 4c. Configure DNS at Ionos
Log into **https://www.ionos.com/** → **Domains & SSL** → click the domain → **DNS**.

Delete any existing `A` / `CNAME` records for `@`, `www`, and `api`, then add:

| Type | Host | Value | TTL |
|---|---|---|---|
| `A` | `@` | `76.76.21.21` | 3600 |
| `CNAME` | `www` | `cname.vercel-dns.com.` | 3600 |
| `CNAME` | `api` | `estimatepro-backend.onrender.com.` | 3600 |

> ⚠️ Trailing dots in CNAME values matter on some registrars — copy the exact target Vercel/Render show you in their dashboards.

### 4d. Wait & Verify
- DNS usually propagates in 5–30 min, max 24 h.
- Back in Vercel & Render dashboards, the domains will flip from "Pending" → "Valid" with auto SSL.
- Open **https://donerightelectricltd.com** → should load your landing page over HTTPS.
- Open **https://api.donerightelectricltd.com/api/health** → should return healthy JSON.

### 4e. Point frontend at the API subdomain (optional cleanup)
Once `api.donerightelectricltd.com` is live, update Vercel env:
- `EXPO_PUBLIC_BACKEND_URL` → `https://api.donerightelectricltd.com`

Then **Redeploy** (Vercel → Deployments → latest → ⋯ → Redeploy).
Also update the same in `render.yaml`'s `CORS_ORIGINS` if needed (already covers your root + www).

## 🆘 Troubleshooting

| Symptom | Fix |
|---|---|
| Vercel build fails on `expo export` | Ensure `frontend/yarn.lock` is committed (it is, commit `49a8afd`). |
| Render build fails on `pip install` | Check `backend/runtime.txt` exists (we created it). Bump to `3.12` if a wheel is missing. |
| API calls 404 on prod | Check `EXPO_PUBLIC_BACKEND_URL` is set on Vercel **without** trailing slash. |
| CORS error in browser | Make sure `CORS_ORIGINS` on Render includes your exact frontend origin (incl. protocol). |
| `/login` works locally but 404 on Vercel | Expo Router needs `cleanUrls: true` (already in `vercel.json`). |
| Domain shows "Invalid Configuration" | DNS hasn't propagated yet — wait 30 min and recheck Vercel/Render dashboards. |

When stuck, paste the exact error message and I'll fix it.
